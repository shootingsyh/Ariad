# 游戏项目需求文档模板

供 PM 编写/维护 `.ariad/docs/REQUIREMENTS.md` 时套用。用法：

- 反推 baseline 时，按下面的分类逐类盘点上一版**已经实现**的东西，只写已实现、已能玩到的；没实现的不要写进 baseline。
- 写新版时，在同一结构上增删改，并在文档末尾用一段人读的话说明「相对上一版改了什么」（delta）。
- 全文保持 high-level、人可读：写产品应该是什么样，不写实现细节、不写任务拆分。细节由 TL 在 feature 文档里落实。

## 1. 产品概述
游戏类型与一句话定位；目标玩家；核心体验（玩家大部分时间在做什么、乐趣来自哪里）；目标平台与发布形态（如 Steam/桌面/主机、单机或联网）。

## 2. 核心玩法
核心循环（进入→行动→反馈→成长的闭环）；主要玩法模式；胜负/推进条件；难度曲线意图。

## 3. 游戏系统
逐个系统写清玩家可见行为：战斗/对抗系统、角色与成长、资源与经济、装备与道具、技能/能力、存档点与失败处理等（按项目实际有的写，没有的系统不列）。

## 4. 内容
关卡/章节结构与数量级；剧情与叙事载体（对话、过场、文本）；任务与支线；可收集/可解锁内容。只写范围与意图，具体关卡设计留给后续版本文档。

## 5. 表现与美术
美术风格与调性（参考基准一句话）；角色与场景的呈现方式（立绘/模型/动画要求）；特效与打击感；过场/CG。各平台发布面（商店页、标题画面）不得出现内部调试信息。

## 6. 音频
音乐（场景/BGM 覆盖范围）；音效（战斗、UI、环境）；语音（如有：覆盖范围与语言）。

## 7. UI 与 UX
主要界面清单（标题、菜单、战斗 HUD、结算、设置等）；操作方式（键鼠/手柄/触屏）；引导与新手教学；无障碍与可读性底线（字号、对比、色盲友好如适用）。

## 8. 存档与生命周期
存档方式（手动/自动/多槽位）；读档与损坏恢复；新周目/继承（如有）；设置项与持久化。

## 9. 性能与平台
目标帧率与分辨率；最低运行环境；各目标平台的输入与窗口形态；打包与分发形态。

## 10. 质量底线
可清关/可通关是硬底线：从正常入口开始能完整玩到结局；不得有阻断性缺陷（卡死、无限加载、存档损坏）；崩溃与异常退出的可接受范围。

## 11. 发布就绪
商店页素材（截图、预告、描述文案）；年龄分级与合规；本地化范围；版本号与更新策略（如适用）。
